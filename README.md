# CS-360-Mobile-Architect-Programming- Weight Tracker App

In this course we were tasked with creating a functional mobile android app that uses a database to store users weight entries and login credentials. The weight tracker app is needed to allow users to create a user account and store their credentials for the next login. They also needed to be able to make daily weight entries that can be viewed, edited, and deleted as needed. They also needed to be able to set weight goals that produces a notification when they reach it. The screens needed to complete these tasks were a login, home, add, edit, and a goal screen. When designing these screens, I made sure to try and make the design layout as intuitive and easy to use as possible. I didn’t want to overcomplicate things especially since my app is more so targeted towards beginners or those who need something simple and not overly complex to track their weight. 

The first thing I did before I began coding was design my screens and color schemes as much as possible to serve as my outline. After I have created a general outline of what my app will do, I move forward with the coding process in increments and find that it is so much to troubleshoot errors this way. I also like to do frequent tests to make sure that the app is functioning as desired. This course taught me the importance of thinking of the potential limitations of the devices and making sure that my application can reach the broadest audience possible. It is always a good idea to get an outline developed first then code incrementally to reduce mistakes and errors as much as possible.

I tested my code periodically throughout the development process by running the application on a virtual machine. I tested through multiple stages of development to make sure that the changes I implemented worked as intended. This process is important because you don’t want to end up at the end of the project and receive a bunch of errors and you are unable to easily find it and fix it. A small error can cause major problems if not addressed earlier enough in the developmental process. I had to be a bit innovative when it came down to getting the date selection for my weight entries correct. I was facing some difficulty with this step to the point where I changed how the date would be entered into the app. After some research and trial and error I was able to get it to work as a calendar selection as I originally wanted it to. I think that I was most successful in designing the UI for my app. The other sections need more work in my opinion. Even though this was my best work right now, doesn’t mean that it is satisfactory to what I want to represent me.
